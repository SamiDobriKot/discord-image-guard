# Discord Image Guard

Discord-бот для защиты сервера от повторяющихся изображений. Он индексирует
картинки во всех каналах, которые видит, ищет совпадения по SHA-256 и pHash
и применяет выбранное действие: бан, удаление сообщений или интерактивное
уведомление с кнопками.

Хеши и служебные данные хранятся только в локальной базе SQLite и никогда
не публикуются в Discord.

## Возможности

- Слушает все сообщения с изображениями на всех серверах, где у бота есть доступ.
- Считает SHA-256 и 64-битный pHash, хранит их локально.
- Ищет точные совпадения по SHA-256 и похожие изображения по pHash.
- Настраиваемый порог: сколько сообщений должно совпасть.
- Настраиваемое окно времени; окно скользящее — каждое новое совпадение продлевает его.
- Режим «только разные каналы» для отслеживания кросспостинга.
- Режим «несколько пользователей»: счётчик общий, в отчётах перечисляются все авторы.
- Три действия:
  - **бан** — блокирует всех авторов из группы; можно задать срок и авторазбан;
  - **удаление** — удаляет сообщения и продолжает удалять новые дубликаты;
  - **уведомление** — присылает сообщение с кнопками и живым счётчиком.
- В отчёте об удалении есть кнопка **«Прекратить удаление»**.
- Временные баны хранятся в SQLite и переживают перезапуск; `/bans` показывает активные.
- Отчёты о результатах и отдельный канал для уведомлений.
- Доступ по ролям; бот проверяет роль при каждом вызове.
- Роли-исключения: сообщения доверенных ролей не индексируются и не проверяются.
- Кнопки удаления и бана проверяют права нажавшего.
- Не обрабатывает одно и то же вложение повторно, ловит картинки,
  добавленные при редактировании сообщения.

## Как работает обнаружение

1. Бот получает сообщение, фильтрует вложения-изображения и считает SHA-256
   и pHash. Запись сохраняется в локальную базу.
2. Если по этому изображению уже есть активный инцидент, новое сообщение
   добавляется в него: счётчик увеличивается, окно продлевается.
3. Иначе бот собирает группу совпадений за текущее окно:
   - по умолчанию — только сообщения этого же пользователя;
   - при включённом режиме нескольких пользователей — сообщения всех авторов;
   - совпадение по SHA-256 или по pHash с расстоянием не больше заданного допуска.
4. Если в группе не меньше N сообщений (N включает первое), срабатывает действие.
5. Режим «только разные каналы» требует, чтобы в группе было минимум два канала.
6. Окно скользящее: каждое новое совпадение отодвигает момент завершения.

Окно не может быть больше срока хранения хешей (`HASH_RETENTION_HOURS`):
иначе старые совпадения уже удалены. По умолчанию хранение — 24 часа,
окно — 1 час.

### Бан

Бот банит всех авторов из группы. Вместе с баном Discord удаляет сообщения
пользователя за последние `min(окно, 7 дней)`; бот дополнительно удаляет
сообщения из инцидента. В канал отчётов приходит результат: кто забанен,
сколько сообщений удалено, что уже отсутствовало и где были ошибки.

Если в `/behavior` задан `duration`, бан временный. Бот сохраняет срок в SQLite,
раз в минуту проверяет истечение и снимает бан. Если Discord не дал разбанить
(например, роль бота ниже), попытка повторится через час. После перезапуска
сроки не сбрасываются: просроченные баны снимаются при старте.

### Удаление

Бот сразу удаляет все сообщения группы и переходит в режим мониторинга.
Пока окно не истекло, каждое новое совпадение удаляется, счётчик и отчёт
обновляются, окно продлевается. Когда окно заканчивается, в отчёт добавляется
итог и мониторинг останавливается.

В отчёте есть кнопка **«Прекратить удаление»**: она останавливает мониторинг,
убирает кнопку и фиксирует результат. Нажать её может администратор или
участник с правом «Управлять сообщениями» из разрешённых ролей.

### Уведомление

Бот отправляет сообщение с количеством совпадений, списком пользователей,
ссылками на сообщения и кнопками:

- **Удалить сообщения**;
- **Забанить пользователей**.

Пока окно активно, каждое новое совпадение увеличивает счётчик и продлевает
окно. После завершения окна счётчик фиксируется, но кнопки остаются рабочими.
Действие по кнопке проверяет роль и право Discord у нажавшего.

## Команды

| Команда | Назначение |
| --- | --- |
| `/channels report:#канал [notify:#канал]` | Канал отчётов и, необязательно, отдельный канал уведомлений. Если `notify` не указан, уведомления идут в канал отчётов. |
| `/behavior action:<Бан\|Удаление сообщений\|Уведомление> [duration]` | Что делать при срабатывании порога. `duration` работает только с баном: `7d`, `12h`, `0`/`навсегда`. |
| `/detection count:<2–100> window:<время> cross_channel:<True/False> [phash_distance:<0–64>] [multi_user:<True/False>]` | Порог, окно, режим разных каналов, допуск pHash и режим нескольких пользователей. |
| `/bans` | Показать активные временные баны и время до разбана. |
| `/roles add role:@роль` | Добавить роль с доступом (только администратор). |
| `/roles remove role:@роль` | Убрать роль (только администратор). |
| `/roles list` | Показать роли с доступом (только администратор). |
| `/roles clear` | Убрать все роли (только администратор). |
| `/roles exclude role:@роль` | Не проверять сообщения этой роли (только администратор). |
| `/roles include role:@роль` | Снова проверять сообщения роли (только администратор). |
| `/roles excluded` | Показать роли-исключения (только администратор). |
| `/settings` | Показать текущие настройки и статистику. |

Формат окна: `45s`, `30m`, `2h`, `1d`. Без единицы значение считается
в минутах: `30` — это 30 минут. Максимум — 30 дней.

## Доступ

- Владелец сервера имеет доступ всегда, даже без права «Администратор».
- Администраторы сервера имеют доступ всегда.
- `/roles` доступна **только** администраторам и владельцу.
- Остальные команды доступны ролям, добавленным через `/roles`.
- Участники без администратора и без выбранной роли не могут пользоваться
  командами: бот отвечает «нет доступа». Кнопки уведомлений им тоже недоступны.
- Роли, добавленные через `/roles exclude`, полностью исключаются из проверки:
  их сообщения не индексируются и не участвуют в детекции.
- Для кнопки «Удалить сообщения» нужно право **«Управлять сообщениями»**.
- Для кнопки «Забанить пользователей» нужно право **«Банить участников»**.
- Бот должен иметь эти права сам, а его роль — стоять выше роли нарушителя.

Discord не позволяет боту управлять видимостью команд по ролям без
пользовательского OAuth2-токена. Поэтому команды, кроме `/roles`, видны
в списке, но бот отклоняет их вызов без нужной роли. `/roles` скрыта от всех,
кроме администраторов. Если нужна полная невидимость остальных команд,
настройте их права вручную в **Server Settings → Integrations**.

## Установка

### 1. Приложение Discord

1. Откройте <https://discord.com/developers/applications> → **New Application**.
2. Перейдите в **Bot** → **Reset Token** и скопируйте токен.
3. Включите **Message Content Intent** в разделе **Privileged Gateway Intents**.
   Без этого Discord не присылает содержимое сообщений и вложения.
4. Пригласите бота по ссылке (замените `ВАШ_APP_ID`):

```
https://discord.com/oauth2/authorize?client_id=ВАШ_APP_ID&permissions=93188&scope=bot%20applications.commands
```

`permissions=93188` — это:

- «Просмотр каналов»;
- «Отправка сообщений»;
- «Встраивание ссылок»;
- «Чтение истории сообщений»;
- «Управление сообщениями»;
- «Банить участников».

`scope=applications.commands` нужен для слэш-команд.

### 2. Запуск

Нужен Python 3.10+.

Windows (PowerShell):

```powershell
cd discord-image-hasher
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
python bot.py
```

Linux / macOS:

```bash
cd discord-image-hasher
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
python bot.py
```

В `.env` вставьте токен:

```dotenv
DISCORD_TOKEN=ваш_токен
```

Если PowerShell запрещает активацию venv:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

### 3. Первичная настройка

На сервере:

```
/channels report:#модерация notify:#оповещения
/behavior action:Уведомление
/detection count:3 window:1h cross_channel:False phash_distance:8 multi_user:False
/roles add role:@модераторы
/roles exclude role:@доверенные
# временный бан на 7 дней вместо уведомления:
/behavior action:Бан duration:7d
```

После этого бот начнёт индексировать новые изображения. Сообщения, отправленные
до запуска, не индексируются: бот не хранит историю каналов.

## Настройки `.env`

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DISCORD_TOKEN` | — | Токен бота (обязательно). |
| `DATABASE_PATH` | `data/guard.sqlite3` | Путь к базе SQLite. |
| `HASH_RETENTION_HOURS` | `24` | Сколько часов хранить изображения и хеши; `0` — без ограничения. |
| `IGNORE_BOTS` | `true` | Игнорировать сообщения других ботов. |
| `MAX_DOWNLOAD_MB` | `32` | Максимальный размер скачиваемого изображения. |
| `MAX_CONCURRENT_HASHES` | `4` | Сколько изображений обрабатывать одновременно. |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`. |

## Приватность

- SHA-256, pHash и метаданные сообщений хранятся только в `DATABASE_PATH`.
- Изображения и их хеши удаляются через `HASH_RETENTION_HOURS` (по умолчанию 24 часа).
  Очистка выполняется при старте и раз в час; закрытые инциденты старше срока
  тоже удаляются. Открытые уведомления хранятся, пока их не обработают.
- Бот не публикует хеши и не пересылает файлы.
- Сами изображения не сохраняются: в базе только имя файла, ссылка на вложение
  и идентификаторы сообщений.
- Превью в отчётах и уведомлениях строятся только из `https`-ссылок Discord CDN;
  сторонние адреса отбрасываются.
- Имена файлов и служебный текст очищаются от управляющих символов и markdown,
  поэтому пользовательские данные не могут подменить содержимое embed.
- Ссылки на вложения в Discord временные; превью в старых отчётах может
  перестать отображаться, но текст отчёта и ссылки на сообщения остаются.

## Ограничения

- Обрабатываются только форматы, которые открывает Pillow. SVG и подобное
  пропускается.
- Файлы больше `MAX_DOWNLOAD_MB` пропускаются.
- Для GIF/WebP pHash считается по первому кадру, SHA-256 — по всему файлу.
- Бот не сканирует историю каналов и не индексирует сообщения, отправленные
  до его запуска.
- pHash — приблизительный: при большом допуске возможны ложные срабатывания.
- В режиме нескольких пользователей бан затрагивает **всех** авторов группы.
- Параметр `duration` в `/behavior` виден всегда: Discord не умеет скрывать
  опции в зависимости от выбранного действия. Он действует только при бане.
- Временный бан снимается по сроку, даже если пользователя параллельно
  забанили вручную навсегда. Управляйте сроками через бота.
- Бот не может забанить владельца сервера или участника с ролью выше своей.
- Без **Message Content Intent** вложения приходят пустыми.
- Discord может синхронизировать глобальные команды до часа.

## Частые проблемы

**Команды не появляются.** Проверьте, что бот приглашён со scope
`applications.commands`, и что команды синхронизированы. Discord может
обновлять глобальные команды до часа. `/roles` видна только администраторам.

**Команда видна, но бот отвечает «нет доступа».** Пользователь не входит
в роль, добавленную через `/roles`, и не является администратором. Админ
может выдать доступ командой `/roles add`.

**Бот не реагирует на картинки.** Проверьте:
- выбран ли канал отчётов (`/channels`);
- включён ли **Message Content Intent**;
- хватает ли сообщений для порога;
- не истекло ли окно;
- не включён ли режим «только разные каналы» при публикациях в одном канале;
- не включён ли режим одного пользователя, когда картинку присылают разные люди.

**`403 Forbidden` при удалении или бане.** У бота нет нужного права, либо его
роль ниже роли нарушителя. Проверьте права бота в канале и положение его роли
в списке ролей.

**Уведомление пришло, но кнопка не срабатывает.** У нажавшего нет права
«Управлять сообщениями» или «Банить участников», либо он не входит в роль
с доступом. Бот сообщит причину в эфемерном ответе.

**`sqlite3.OperationalError: unable to open database file`.** Каталог из
`DATABASE_PATH` недоступен для записи. Создайте его или измените путь.

**После обновления бота пропали старые команды.** Перезапустите бота: при
старте он синхронизирует актуальный список команд.

## Тесты

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Покрыты: SHA-256 и pHash, устойчивость pHash к сжатию, фильтр вложений,
группировка совпадений, порог и режим разных каналов, SQLite-хранилище,
инциденты, сборка отчётов и уведомлений, индексация сообщений.
